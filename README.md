# Shelfbound

An iPhone reader for fanfic, manga and manhwa. Content comes from community-run **repos** of sandboxed **sources**. The app ships with no sources and no default repo.

What works: the source system and signed repos, a library grouped by fandom with continue reading and new-chapter badges, work pages, the text reader (themes, glossary, pull for the next chapter), the paged manga reader (right to left or left to right), the vertical manhwa reader, offline downloads, and background update checks with notifications.

## What's here

| Path | What it is |
| --- | --- |
| `Sources/ShelfCore` | Shared models (works, chapters, manifests), domain allow-list, reader HTML builder |
| `Sources/SourceKit` | Runs a source's JavaScript in its own JavaScriptCore VM with a small `host` API |
| `Sources/RepoKit` | Reads a repo's `index.json`, checks SHA-256 and Ed25519 signatures, pins keys, installs sources |
| `Sources/LibraryKit` | The library: records, reading positions, grouping by fandom, update checks |
| `Sources/DownloadKit` | The download queue: background transfers, per-host limits, retries, storage cap and clean-up |
| `App/` | SwiftUI app: Library, Browse, Settings, the three readers, downloads. Project generated by XcodeGen |
| `sdk/shelf-repo` | Node CLI for repo maintainers: `keygen`, `build` (sign), `run` (test a source) |
| `examples/repo-template` | A starter repo with one public-domain example source (Project Gutenberg) |
| `examples/webnovel-repo` | Web novels: a Novel Updates discovery source plus a source that reads translators' sites |
| `examples/ao3-repo` | Archive of Our Own, with search filters and a slow rate limit. Not bundled with the app |

## Run it on your Mac

Needs macOS 14 and Xcode 15.4 or newer.

```sh
brew install xcodegen
cd App
xcodegen generate
open Shelfbound.xcodeproj
```

Pick an iPhone simulator and press Run.

Tests:

```sh
swift test                                   # Swift packages, from the repo root
cd sdk/shelf-repo && npm install && npm test # repo CLI (installs cheerio for host.select)
cd examples/ao3-repo && npm test             # example sources, offline against saved pages
cd examples/webnovel-repo && npm test
```

Background update checks can be triggered in the simulator from Xcode's debugger: pause the app and run
`e -l objc -- (void)[[BGTaskScheduler sharedScheduler] _simulateLaunchForTaskWithIdentifier:@"app.shelfbound.Shelfbound.refresh"]`, then continue.

To try a repo locally:

```sh
cd examples/repo-template
npx ../../sdk/shelf-repo keygen
npx ../../sdk/shelf-repo build
npx http-server dist -p 8080     # or any static server
```

The app only accepts `https` repos, so for the simulator push `dist/` to GitHub Pages, or tunnel the local server over HTTPS.

## How sources are sandboxed

- One JavaScriptCore VM per source. No network, file or timer APIs exist inside it.
- The only way out is `host.fetch`, which reaches only the domains in the source's manifest (redirects included) and is rate-limited to about one request per second per source, or slower if the manifest asks. The app backs off when a site answers 429 or 503.
- Results are JSON, validated into Swift types before the UI sees them.
- Sites behind a Cloudflare check: the person passes it themselves in an in-app browser sheet ("Verify in browser"). The app keeps that site's cookies and browser User-Agent until the check expires, then asks again. Downloads from the site pause, and the person gets a notification, rather than the downloads failing. The app never solves the check itself.
- The text reader shows chapter HTML with page JavaScript turned off and a strict Content-Security-Policy.
- Packages are signed by the repo's key. The app pins the key on first add and refuses packages that don't match.

See `examples/repo-template/README.md` for the source API.

## Content policy

Shelfbound doesn't host content or list repos. Only add sources for sites whose terms allow it, and respect their rate limits and access rules.
