# Shelfbound

An iPhone reader for fanfic, manga and manhwa. Content comes from community-run **repos** of sandboxed **sources**. The app ships with no sources and no default repo.

What works: the source system and signed repos, a library grouped by fandom with continue reading and new-chapter badges, work pages, the text reader (themes, glossary, pull for the next chapter), the paged manga reader (right to left or left to right), the vertical manhwa reader, offline downloads, and background update checks with notifications.

## What's here

| Path | What it is |
| --- | --- |
| `Sources/ShelfCore` | Shared models (works, chapters, manifests), domain allow-list, reader HTML builder |
| `Sources/SourceKit` | Runs a source's JavaScript in its own JavaScriptCore VM with a small `host` API |
| `Sources/RepoKit` | Reads a repo's `index.json`, checks SHA-256 and Ed25519 signatures, pins keys, installs sources |
| `Sources/LibraryKit` | The library: records, reading positions, grouping by fandom, update checks |
| `Sources/DownloadKit` | The download queue: background transfers, per-host limits, retries, storage cap and clean-up |
| `App/` | SwiftUI app: Library, Browse, Settings, the three readers, downloads. Project generated by XcodeGen |
| `sdk/shelf-repo` | Node CLI for repo maintainers: `keygen`, `build` (sign), `run` (test a source) |
| `examples/repo-template` | A starter repo with one public-domain example source (Project Gutenberg) |
| `examples/webnovel-repo` | Web novels: a Novel Updates discovery source plus a source that reads translators' sites |
| `examples/ao3-repo` | Archive of Our Own, with search filters and a slow rate limit. Not bundled with the app |

## Run it on your Mac

Needs macOS 14 and Xcode 15.4 or newer.

```sh
brew install xcodegen
cd App
xcodegen generate
open Shelfbound.xcodeproj
```

Pick an iPhone simulator and press Run.

Tests:

```sh
swift test                                   # Swift packages, from the repo root
cd sdk/shelf-repo && npm install && npm test # repo CLI (installs cheerio for host.select)
cd examples/ao3-repo && npm test             # example sources, offline against saved pages
cd examples/webnovel-repo && npm test
```

Background update checks can be triggered in the simulator from Xcode's debugger: pause the app and run
`e -l objc -- (void)[[BGTaskScheduler sharedScheduler] _simulateLaunchForTaskWithIdentifier:@"app.shelfbound.Shelfbound.refresh"]`, then continue.

To try a repo locally:

```sh
cd examples/repo-template
npx ../../sdk/shelf-repo keygen
npx ../../sdk/shelf-repo build
npx http-server dist -p 8080     # or any static server
```

The app only accepts `https` repos, so for the simulator push `dist/` to GitHub Pages, or tunnel the local server over HTTPS.

## How sources are sandboxed

- One JavaScriptCore VM per source. No network, file or timer APIs exist inside it.
- The only way out is `host.fetch`, which reaches only the domains in the source's manifest (redirects included) and is rate-limited to about one request per second per source, or slower if the manifest asks. The app backs off when a site answers 429 or 503.
- Results are JSON, validated into Swift types before the UI sees them.
- Sites behind a Cloudflare check: the person passes it themselves in an in-app browser sheet ("Verify in browser"). The app keeps that site's cookies and browser User-Agent until the check expires, then asks again. Downloads from the site pause, and the person gets a notification, rather than the downloads failing. The app never solves the check itself.
- The text reader shows chapter HTML with page JavaScript turned off and a strict Content-Security-Policy.
- Packages are signed by the repo's key. The app pins the key on first add and refuses packages that don't match.

See `examples/repo-template/README.md` for the source API.

## Widgets and Live Activities

The `ShelfboundWidgets` extension has Continue reading and New chapters widgets for the Home Screen and Lock Screen, plus a Live Activity while chapters download. The app writes a small snapshot into the App Group `group.app.shelfbound`; the widgets only read it. To build it, pick your team under Signing & Capabilities for both targets and let Xcode register the App Group. Without the group the app still runs and the widgets stay empty.

## Your own files

Library › the import button (or Settings › Import books and comics) adds EPUB, PDF and CBZ files from Files or iCloud Drive, and "Open in Shelfbound" works from Files, Mail and other apps. Files are copied into the app, so the original can go.

- **EPUB:** chapters follow the book's table of contents; files it doesn't name join the chapter before them. Images are kept. Picture-only EPUBs (most manga EPUBs) open in the image readers instead, right to left when the book says so.
- **CBZ:** each folder in the archive is a chapter. ComicInfo.xml gives the title, series, writers and manga direction; long strips open in the vertical reader.
- **PDF:** pages are drawn once at import and read in the paged reader, split into chapters by the PDF's bookmarks.

DRM-protected books can't be opened. Imported works sit under "Your files" and are deleted from the work's menu (the backup file keeps their reading place, not the files).

## App Store build

The `Shelfbound App Store` scheme builds the App Store version (configuration `AppStore`, Swift flag `APP_STORE`). `docs/app-store/` has the submission steps, listing, review notes, privacy policy and subscription plan, and the **App Store build** workflow signs and uploads to TestFlight once the account secrets are set.

## Importing from other apps

Settings › Import library reads a Paperback backup (`.pas4`, a zip), an Aidoku backup (`.aib`), or a list of links such as AO3 bookmarks. Each work is found on an installed source, by its link when a source has `idFromURL`, otherwise by searching its title, and read chapters carry over by chapter number. The backup readers were written from the apps' formats without a real backup to test against, so try one and report what doesn't come through.

The app uses [ZIPFoundation](https://github.com/weichsel/ZIPFoundation) (MIT) to open Paperback backups.

## Accounts

Settings › Accounts lists installed sources you can sign in to, such as AO3. You sign in on the site's own page inside the app; Shelfbound keeps the site's sign-in cookie in the Keychain and never sees your password. Signed in to AO3 you can:

- read works restricted to registered users,
- browse your Bookmarks, Marked for Later, History and Subscriptions, and **Import** them into the library (grouped by fandom like everything else), or turn on **Keep in sync** so new ones are added on every update check,
- use **Mark for Later**, **Subscribe** and **Kudos** on a work's page.

Chapters you read while signed in count in your AO3 history, since AO3 records visits itself. Syncing only ever adds to the library; nothing on your AO3 account changes unless you tap one of those buttons.

## Backup and restore

Settings › Back up library saves one JSON file with the library, reading places, highlights, glossaries, per-work settings, app settings, and the repos and sources you had. Settings › Restore from backup merges it back: works in the backup replace the same works here, repos are added again and sources are reinstalled from them. Sign-ins aren't in the backup, so sign in again afterwards. Sideloaded apps can expire, so keep a recent backup in Files or iCloud Drive.

## Highlights and notes

In a fic or novel chapter, select text and choose **Highlight** or **Add Note**. Tap a highlight to edit its note, share it as a quote, or delete it. A work's page lists all its highlights under **Highlights and notes**, and **Export** shares them as Markdown. Highlights are stored with a little text either side, so they stay put if the source changes a chapter's markup, and they follow a work when it moves to another source.

## On-device translation

On iOS 18 and later, the translate button in the text reader (or **Translate chapters** on a work's page) translates each chapter with Apple's Translation framework. It runs on the device, and iOS asks to download a language the first time. **Show original** switches back. Translations are cached, so reopening a chapter is instant. Paragraphs lose inline formatting such as italics while translated. On iOS 17.4 and later, **Translate** next to a work's summary opens the system translation sheet.

## Panel by panel

In the paged manga reader, the panels button in the top bar zooms to one panel at a time. Tapping the next-page side moves to the next panel, and past the last panel it turns the page. Panels are found on the device by cutting the page along its gutters, in manga order (right to left) or comic order as the work is set. Splash pages and borderless art show whole. The choice is saved per work.

## iPad, Mac, Shortcuts and Siri

- **iPad:** in a wide window, Library, Browse and Settings move to a sidebar. The app works in Split View, Slide Over and all four orientations. With a keyboard, the arrow keys and space turn pages in the manga reader. Cmd-R checks for new chapters, and Cmd-1, Cmd-2 and Cmd-3 switch sections (hold Cmd to see the list).
- **Mac:** on an Apple silicon Mac, pick **My Mac (Designed for iPad)** as the run destination in Xcode. The same commands appear in a Library menu.
- **Shortcuts and Siri:** "Continue reading in Shelfbound", "Check Shelfbound for new chapters", "How many new chapters in Shelfbound" and "Open … in Shelfbound". They also show up as actions in the Shortcuts app, where Check for New Chapters and Get New Chapter Count return a number you can use in automations.

## New-chapter alerts on Apple Watch

Each work that gets new chapters has its own alert, such as "Hollow Tide: 3 new chapters, up to Chapter 87". A later check replaces that work's alert instead of adding another, and when more than four works update at once a single summary covers them. A paired Apple Watch mirrors these alerts. **Download** and **Mark as Read** work from the watch or the Lock Screen without opening the app. To get them on the watch, leave Shelfbound's notifications on under Watch app › Notifications on the iPhone.

## Content policy

Shelfbound doesn't host content or list repos. Only add sources for sites whose terms allow it, and respect their rate limits and access rules.
